# Fix Now (1.6.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the known breakages and funnel blind spots before the New Year push, shipped as site fixes plus app version 1.6.1.

**Architecture:** Site fixes are template and JSON edits rendered by `server/index.ts`. The ratings ask moves from a UI celebration flag to a pure decision module fed by stored daily logs. Telemetry stays count-only; new signals are new event names added to the mirrored client and server allowlists.

**Tech Stack:** Expo / React Native (TypeScript), Express, Jest (`TZ=America/Los_Angeles`), expo-store-review, AsyncStorage.

**Spec:** `docs/superpowers/specs/2026-11-10-new-year-2027-design.md` (Part 1). Part 2 (1.7.0) and Part 3 (launch runbook) get their own plans.

## Global Constraints

- Branch: `claude/new-year-2027`. Never work in or copy the repo to iCloud.
- Human gates: merging to `main` (deploys production), the Railway console, every App Store Connect action, and the build upload are Brett's. This plan stops at "ready for Brett".
- Prices do not change. No paywall is added to onboarding.
- Telemetry is counts per device per day by event name. No payloads, no content, no new identifiers.
- Never remove a name from `server/telemetry-events.ts`; installed builds keep sending what they shipped with.
- Every tappable is a `Pressable` with a pressed style and `hitSlop`; follow "UI conventions" in `CLAUDE.md`.
- Public copy carries user-facing features only, and no em dashes.
- Use plain `node` / `npx` (the Homebrew `node@22` keg is broken). Tests: `npm test`. Types: `npm run check:types`. Lint: `npm run lint`.
- App Store ID `6757996708`.

## Review Focus

1. A user who was already asked for a review on an earlier version (`today_review_requested` is set) must never be asked again. Pinned in Task 3.
2. A day with no scheduled habits is not a "completed day", and neither is a day where one of two scheduled habits is done. Pinned in Task 3.
3. A completion logged by the widget, a notification action, or Apple Health while the app is in the background must not fire the ask in the background; it fires the next time Today is on screen and unblocked. Pinned in Task 3.
4. The app left open across midnight must not count the new day as complete. Pinned in Task 3.
5. The paywall opened with no `source` param, or by an old binary sending plain `paywall_viewed`, must still be counted and never rejected. Pinned in Task 4.
